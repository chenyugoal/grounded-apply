# ADR 0006: Bounded local application pilot

- **Status:** Accepted; bounded pilot implemented and verified (see SESSION_HANDOFF.md)
- **Date:** 2026-09-04

The immediate personal-use target is one local user on the verified macOS/Python
environment: UTF-8 resume onboarding, explicit review, manually supplied job-page
text and URL, a transparent evidence matrix, selected traceable resume/PDF and
copy-paste answers, and a manual application history. No model provider, network
fetching, scraping, browser fill, or submission is introduced by this pilot.
Hosted OS/interpreter support, richer resume formats, background discovery,
automatic expiry, full filesystem backup, and broad semantic classification
remain separate roadmap work. Their absence must be documented without claiming
that the complete multi-platform product is released.

Exact resume-line extraction proposes only copied career text and explicitly
labeled name/contact fields. Users select what to store and separately approve
each fact. Import vocabulary 1 retains its definitions and replay identities.
Vocabulary 2 explicitly adds candidate_name/contact_email/contact_phone/
contact_location/contact_url as bounded strings. Workflows record the smallest
vocabulary needed, and the dispatcher validates records against that vocabulary;
unknown versions fail closed. No legal identity, sensitive eligibility answer,
ownership upgrade, or unstated employment association is inferred.

Job capture stores immutable user-supplied UTF-8 text with its original URL,
digest, capture time, and method. It is not evidence that the application fetched
or verified a live page. Requirements preserve exact source spans, quotation
versus inference, and deterministic classification provenance. Prompt-like text
stays inert. Keyword overlap may retrieve candidate evidence but cannot establish
that a requirement is met, calculate a hiring probability, or rank applicants.
The matrix identifies uncertainty and gap questions for human review.

Material generation uses a named deterministic template over approved ClaimPackets.
Every factual unit retains its claim IDs and exact approved text. The user selects
the facts to emphasize. Single-valued conflicting identity/employment facts block
use; multi-valued skills and career bullets remain independent facts. Selection
cannot hide explicitly contradicted records for the same subject/type. All units
are revalidated against current provenance, retirement, scope, dates, and evidence
before rendering, approval, or recording manual submission. Missing identity,
unsupported text, or PDF extraction failures prevent readiness.

Generated bytes, structure, validation, and hashes are stored in the local SQLite
database so the encrypted database backup and allowlisted portable deletion cover
the complete pilot state. Explicit exports are copies outside this managed state;
preview and documentation name those exclusions. Template output is private and
never used as a diagnostic log. No raw model prompt or hidden reasoning exists.

Readiness and submission history are distinct. Readiness requires explicit human
approval of an unchanged material digest. Recording `applied` requires explicit
confirmation that the human submitted and preserves exact immutable materials
and answers; it performs no external action. Events and snapshots are append-only.
Changed claims or materials invalidate subsequent readiness/submission checks.

The release gate is the complete synthetic CLI workflow, adversarial truth/privacy
tests, real PDF rendering and visual inspection, encrypted backup/restore of the
new tables, safe deletion, and a fresh installed-package run. Until those pass,
personal use remains unavailable. Exact supported dependencies and limitations
must appear in the README, development guide, and live checkpoint.
